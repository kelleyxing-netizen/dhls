# MVP人工节点与验收

适用独立演示账号和独立运行目录。先按 [README](../README.md)完成初始化并记下实际资源编号。所有步骤执行后填写操作者、时间、run或草稿编号、界面和事件证据；下面是待执行规程，不是已发生的真实模型验收记录。

## 正常申请的三个人工点

为避开演示原排期，选择未来一个可用时段，输入场馆、资源、带时区的起止时间、人数和用途。不要把本次示例日期或资源编号硬编码进真实数据；以本次初始化与当前资源检查为准。

| 阶段 | 操作 | 必须核对的事实 |
| --- | --- | --- |
| 准备 | 员工登录/agent，提交完整需求 | 工具实际完成检索、资源检查和PASS校验；缺项须补问 |
| H1之前 | 等待完整预览 | 已持久中断；显示待确认；本run没有草稿 |
| H1 | 核对后点击确认创建 | 返回唯一草稿编号；新草稿状态draft，尚未审核 |
| H2之前 | 切换审核账号看审批列表 | 未提交草稿不在列表中，审核详情不可读取 |
| H2 | 本人到/drafts核对并提交 | 状态submitted，出现submit事件与提交版本 |
| H3之前 | 有场馆审核权的其他管理员打开详情 | 当前权限、规则、容量、冲突和原版本复核有效 |
| H3 | 填写意见并通过 | 状态approved，submit与approve事件顺序和版本一致 |
| 完成 | 员工查看结果 | 能看到意见和事件；原排期、资源占用仍未改变 |

H1文字“确认”不算按钮确认，H1不代替H2，H3只保存审核结论。未配置真实模型时不能在界面上用离线脚本冒充实际模型申请。

## 拒绝与退回

| 场景 | 操作 | 合格标准 |
| --- | --- | --- |
| 拒绝H1 | 在完整预览后选择暂不创建 | run为rejected，草稿新增0、模型调用不超过5 |
| 退回H3 | 申请已提交，审核人填写原因退回 | returned，有submit/return事件；员工看见原因；原占用不变 |
| 无审核授权 | 管理员未执行grant-review即读审核接口 | 不能借角色扩大审核范围 |
| 陈旧页面 | 查看详情后资源或版本改变，再通过 | 409提示刷新复核，旧决定不生效 |
| 确认后刷新 | 重读run和草稿 | 不因GET或恢复重复建草稿、不自动提交 |

## 自动验证与真实效果的区别

`python -m pytest mvp/tests -q`运行实际profile配置、真实HTTP、JWT、LangGraph、SQLite和规则，检索与模型用测试替身。三条工作流分别验证H1拒绝、H1/H2/H3通过及H3退回；不是仅检查页面按钮文字。测试数据全部在pytest临时目录，禁止指向现有MVP运行库。

原测试目录另覆盖五轮预算、越权、CSRF、重复确认、断线和重启等场景。真实模型回答、性能容量、备份恢复演练及生产上线仍须另外留证。该文件不替代用户清单中的逐场景截图Word。
