# MVP知识库

[policy.md](policy.md)是可运行的虚构制度，与项目内置样例及 [原可读副本](../../data/sample_policy.md)对应。[sources.json](sources.json)记录来源、版本、SHA256、资料性质和访问边界；默认制度发生变化会使`doctor`报错，防止演示规则与文字依据悄悄分离。

摘要按去除UTF-8 BOM、统一LF换行后的UTF-8文本计算，与实际知识库的版本口径一致；Windows的CRLF换行本身不算制度变更。

制度每片最多500个Unicode字符、无重叠；本地中文Embedding与FAISS向量检索结合BM25，用RRF融合去重后取top3。问答带来源引用，最近仅保留6个完整成功问答对。首次模型下载后可复用缓存；缓存放在`.runtime/rag/`，不提交仓库或交付包。

普通问答当前所有已登录账号共用一份启动时制度。部门和场馆业务授权不能当作文档ACL，正则脱敏也不是企业级隐私治理。数据库会保留原始问题与回答；真实制度接入前确认授权、版本、脱敏和保留期限。

## 指定正式制度的流程

1. 准备获授权的UTF-8 Markdown，记录来源人、正式版本、适用组织、授权范围及摘要；不将原始真实制度提交公共仓库。
2. 在每次MVP命令前显式传入 `--document <绝对路径>`，服务与维护命令使用同一配置；修改制度后停服并重启。
3. 用固定问题核对引用与拒答，重新适配数据库中的确定性业务规则。真实规则未适配时保持NEEDS_REVIEW，不能靠替换文档或提示词产生PASS。
4. 分别留存制度问答效果、工具契约、安全权限与人工审批证据。真实模型和文档ACL未验收前，不开放真实敏感资料。

`EMBEDDING_OFFLINE=1`只禁Embedding下载，必须已缓存模型；不代表生成API离线。`doctor`只核对本地配置，不启动Embedding或下载模型。
