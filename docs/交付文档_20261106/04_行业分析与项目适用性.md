# 行业分析与项目适用性
历史研究日期 2026年10月23日　整理日期 2026年11月6日

本册将既有行业桌面研究与当前 MVP 对照，帮助判断哪些能力可以参考、哪些需要适配。行业事实和产品能力沿用 10 月 23 日报告快照，没有将其作为 11 月 6 日重新核验的市场数据；完整来源和历史引用保留在原调研报告中。

## 行业问题与本项目范围
场馆资源管理涉及多空间、时间窗、容量、进撤场及恢复缓冲；需求变更同时影响申请版本、交接对象和审批。公开市场规模只能说明业务背景，不能用于估计本项目单量或 ROI。现有材料中的多源重复核对仍是合成需求假设，真实试点应取得脱敏业务样本。

项目先以制度问答、申请准备和人工审批为受控入口。全量活动运营、合同、票务、支付、客户通知和正式占档并非当前交付能力。AI 优先承担阅读与整理，能精确计算的冲突和版本条件保持确定性实现。

## 可参考的产品路径
| 路径或项目 | 借鉴方向 | 适配和验证重点 |
| --- | --- | --- |
| Momentus | 多空间活动与运营协作 | 具体版本、导出权限、实施与采购成本 |
| Skedda 或 AllBooked | 预约请求与授权审批 | 请求与确认占用区别、套餐限制 |
| LibreBooking | 资源、缓冲、并发冲突 | 区间规则、版本来源、许可证 |
| pretalx | 草稿与已发布版本、差异 | 议程与场馆领域差异、授权条款 |
| OpenProject | 变更工作项、责任与协作 | 时间冲突需独立规则，不由任务依赖代替 |
| FullCalendar | 日历与时间轴展示 | Standard 与 Premium 权限分别确认 |

这些是历史研究中的功能参照，不是已安装验证或采购推荐。复制第三方代码前锁定版本、核验具体许可证及依赖，不以旧 README 代替当前授权文件。

## 自建与接入决策
自建轻量工作台能控制来源与人工闸门，适合验证一个场馆的规则；成本在于维护权限、规则、版本和运行保障。二次开发预约平台可复用资源能力，但需要处理数据模型及授权差异。采购平台有利于覆盖长链路，需用同一组样本核验接口、字段、数据地域与总成本。

现阶段优先复用本仓库 MVP 做流程验证，再以需求矩阵比较采购或二次开发。未签认的规则和来源不能通过采购或接入模型自动补齐。
