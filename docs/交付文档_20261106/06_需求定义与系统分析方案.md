# 需求定义与系统分析方案
版本 1.0　编制日期 2026年11月6日

本方案把书面简报、六角色演练、典型事件与现有原型转为可追踪的需求基线。优先完成可控制风险的问答、申请准备和人工审批，再建设多源导入、文档授权和交接摘要。需求状态分“现有原型”“演示规则”“待建设”，不据文档签署推定功能已实现。

## 业务目标与证据链
痛点为来源分散、版本不同步、资源时间冲突、交接责任不清。书面 Brief 限定只读核对与人工交接；当前软件允许在内部创建草稿和保存审核结果，不能向正式排期、合同、支付或通知系统执行写入。

来源 S01 为新提供四份书面资料，S02 为六人访谈 f00 至 f55，S03 为本次明确标注的典型事件演练，S04 为 10 月 23 日行业研究，S05 为当前源码与接口。真实需求签认、规则和样本仍须业务负责人、运营、质量及维护岗位共同完成。

## AI 改造及优先级
| 痛点 | 改造方式 | 优先级及理由 |
| --- | --- | --- |
| 制度查找与重复解释 | 混合检索和带来源回答 | P0 已有基础，限定制度与引用 |
| 申请信息反复整理 | 工具编排和规范预览 | P0 写入前有人确认 |
| 冲突难以解释 | 规则检查加可视化，AI辅助说明 | P0 时间计算由规则负责 |
| 新旧方案和责任不清 | 差异、提交、审核和事件链 | P0 防止错误版本被批准 |
| 多源导入和制度分权 | 映射、快照、文档ACL | P1 依赖正式字段与授权 |
| 交接摘要与优化 | AI生成未结项和责任清单 | P1 先完成数据及规则验证 |

P0 为当前原型控制与试点必须核验，P1 为数据和岗位确认后建设。自动锁档、客户承诺、签约、支付及跨场馆优化不纳入本版；预算、岗位和真实效率基线未经确认不设为承诺。

## 需求规格

### R01 制度问答与引用

优先级 P0。依据 f15 f40，状态为现有原型。

问题不超过2000字符；检索500字符切片、RRF top3，最近6个完整成功问答对。输入不满足时返回明确错误或待核实状态；结果以持久状态与接口事实为准。验收编号 A01，测试编号 T01。

### R02 完整申请与工具顺序

优先级 P0。依据 f10 f31，状态为现有原型。

新申请含场馆、资源、有时区起止、正整数人数、用途；变更另含本人原排期、版本、原因。输入不满足时返回明确错误或待核实状态；结果以持久状态与接口事实为准。验收编号 A02，测试编号 T02。

### R03 容量冲突及规则核验

优先级 P0。依据 f11 f44 f50，状态为演示规则。

按当前资源容量与已批准占用检查；规则不适用返回待人工核实，不产生PASS。输入不满足时返回明确错误或待核实状态；结果以持久状态与接口事实为准。验收编号 A03，测试编号 T03。

### R04 确认后唯一草稿

优先级 P0。依据 f14 f41，状态为现有原型。

先保存完整预览并中断；确认校验所有权、摘要、期限及版本，同run至多一份草稿。输入不满足时返回明确错误或待核实状态；结果以持久状态与接口事实为准。验收编号 A04，测试编号 T04。

### R05 主动提交及授权审核

优先级 P0。依据 f22 f25 f41，状态为现有原型。

本人主动提交；场馆审核授权、禁止自审；过期页面或条件变化不能通过，退回原因必填。输入不满足时返回明确错误或待核实状态；结果以持久状态与接口事实为准。验收编号 A05，测试编号 T05。

### R06 变更与审批记录

优先级 P0。依据 f20 f24 f43，状态为现有原型。

展示原排期与候选差异，事件同事务保存，不允许应用改删；通过不改原排期。输入不满足时返回明确错误或待核实状态；结果以持久状态与接口事实为准。验收编号 A06，测试编号 T06。

### R07 身份与范围隔离

优先级 P0。依据 f40 f41，状态为现有原型。

JWT及CSRF；会话本人可见，审核按当前场馆授权；业务权不等于制度ACL。输入不满足时返回明确错误或待核实状态；结果以持久状态与接口事实为准。验收编号 A07，测试编号 T07。

### R08 故障恢复与预算

优先级 P0。依据 f35 f44，状态为现有原型。

每run至多5次实际模型请求，失败重启不返还；状态恢复不重复创建、不假报成功。输入不满足时返回明确错误或待核实状态；结果以持久状态与接口事实为准。验收编号 A08，测试编号 T08。

### R09 多源只读导入与文档ACL

优先级 P1。依据 f30 f32 f33，状态为待建设。

拟支持3个约定CSV/XLSX模板；保留原行、来源与版本，按正式授权控制制度可见。输入不满足时返回明确错误或待核实状态；结果以持久状态与接口事实为准。验收编号 A09，测试编号 T09。

### R10 AI交接摘要及实际效果验收

优先级 P1。依据 f15 f23 f42，状态为部分材料待建设。

拟以固定30样本核验字段、引用和摘要；不覆盖原值，不形成外部承诺。输入不满足时返回明确错误或待核实状态；结果以持久状态与接口事实为准。验收编号 A10，测试编号 T10。

## 非功能需求和运行边界
N01 权限失败与未确认写入为阻断问题，允许泄露和越权成功次数均为 0。N02 数据一致性要求同 run 或 validation 至多一份草稿，提交和审批事件原子保存。N03 错误保持中文信封及 request_id，不返回密钥和原始异常。N04 原型固定本机地址和单 worker，不把本地验证外推为并发容量承诺。

建议试点性能基线为 100 次本地只读状态请求，在指定 4 核 8GB 测试机、单连接且不含模型调用时 P95 不超过 2 秒；为拟定目标，未实测。生成服务延迟受供应商影响，执行前签认首字、完成时长与并发目标。建议受控试点 RPO 24 小时、RTO 4 小时，以停机备份恢复演练验证，不代表现有高可用能力。

## 验收标准清单
下列 T01 至 T10 是本方案验收测试编号，不冒充仓库现有函数名；执行状态统一为待执行。真实模型行为、离线回归和人工样本核验分开计数。

| 验收 | 样本与执行 | 合格标准 |
| --- | --- | --- |
| A01 | 10条制度题含3条无答案题 | 每个结论引用可定位；无答案题3/3不编造 |
| A02 | 5正常申请及5缺项变更 | 正常5/5满足前置；缺项5/5不建草稿 |
| A03 | 10标注冲突及5边界样本 | 10/10标注冲突被检出；边界按签认规则5/5一致 |
| A04 | 5确认、5拒绝及10次重复确认 | 确认每run1份；拒绝0份；重复无额外草稿 |
| A05 | 5通过、5退回、5陈旧或自审 | 正常状态与记录一致；陈旧或自审0次通过 |
| A06 | 5变更及5事件链抽查 | 差异与快照一致；原排期不变；事件无丢失 |
| A07 | 10越权和CSRF负例 | 数据泄露0，越权写入0 |
| A08 | 超时、断线、重启各3次 | 轮次不返还且不超5；重复草稿0；状态不伪报 |
| A09 | 3模板各10行含缺项和重复 | 30行均可回源；无授权读取0；未建设时不得放行 |
| A10 | 冻结30样本，人工双人评分 | 关键字段候选正确率建议≥95%；确认与来源完整100% |

A10 分母为样本中人工标注的应提取关键字段数，空值与错误均计失败；未执行或前置不足不算通过。不同测试可复用受控样本，但报告须按验收编号列结果，不能将回归用例数量当业务准确率。所有安全阻断项要求 0 缺陷，P1 未实现可明确排除在本次原型验收之外。

## 变更管理与签认
业务负责人签范围及优先级，运营签容量、互斥和缓冲，质量签样本、权限和留存，维护岗位签运行与恢复条件。变更记录需求编号、原因、影响设计及测试、预算和批准日期；未签认项保持待确认，不通过改写提示词绕过业务约束。
