# 上线交付与运行手册
版本 1.0　编制日期 2026年11月6日

本册用于本机单 worker 原型的安装、演示、维护和恢复。企业上线仍需完成 docs/prelaunch-checklist.md；以下命令由维护人员在隔离环境执行，不覆盖现有业务目录。

## 交付与接收清单
| 交付项 | 核对方法 | 接收记录 |
| --- | --- | --- |
| 源码和wheel | 提交号、版本号、SHA256与构建清单 | 接收人 日期 待填写 |
| 配置和模型 | 环境变量表、供应商协议和授权 | 密钥另渠道交接，不入仓库 |
| 数据和制度 | 来源版本、授权、目录、备份摘要 | 演示与真实数据分开 |
| 权限与验收 | 账号岗位、场馆业务权和审核权 | 签认单及证据位置 |
| 运维和培训 | 本手册、恢复记录、已知限制 | 维护及业务负责人签收 |

## 环境准备
Python 3.11及以上；试点建议4核8GB、10GB可用空间，实际用量待测。首次安装和模型下载需网络，Embedding离线不代表生成模型离线。固定127.0.0.1、单worker及实例锁，不直接暴露公网。

下列PowerShell命令从仓库根执行。首次设置独立目录时确认目标为空，已有目录先备份；路径按实际盘符替换。

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e .
$env:CHAT_DATA_DIR = 'D:\dhls-runtime\chat'
$env:RAG_WORK_DIR = 'D:\dhls-runtime\rag'
```

配置来自环境变量，不加载config/default.toml。兼容供应商须配置LLM_PROVIDER、LLM_BASE_URL、LLM_MODEL及密钥，并支持工具协议。服务和维护CLI使用同一CHAT_DATA_DIR。

## 账号与演示初始化
先停止使用同数据目录的服务。账号无默认密码，创建时交互输入12至128字符口令。下面角色、部门和场馆仅用于隔离演示。

```powershell
python scripts/manage_users.py create-user --username demo.employee --display-name '演示员工' --role employee --department sales --venue east
python scripts/manage_users.py create-user --username demo.admin --display-name '演示管理员' --role admin --department operations --venue east
python scripts/manage_agent.py init-demo --username demo.employee
python scripts/manage_agent.py init-demo --username demo.admin
python scripts/manage_agent.py grant-review --username demo.admin --venue east
```

init-demo仅建虚构规则和资源，不恢复已撤销权限或导入生产资源。记录返回的资源与原排期编号。管理员先有场馆业务权，再单独授予审核权，禁止自审。

## 配置密钥与启动
```powershell
$env:DEEPSEEK_API_KEY = [System.Net.NetworkCredential]::new('', (Read-Host '模型密钥' -AsSecureString)).Password
python -m dhls
```

密钥仅在当前后端进程环境提供，不打印、不写.env、源码或前端。默认端口8000，需要更换可使用python -m dhls --port 8001。维护窗口结束后关闭相应进程环境；不把模型密钥用作JWT签名密钥。默认独立JWT签名材料在业务目录，恢复时须一并保护。

## 首次验证与日常操作
打开http://127.0.0.1:8000/login，用隔离样本验证问答、预览拒绝零草稿、确认唯一草稿、本人提交及管理员差异复核和通过退回；另核验他人会话、未提交草稿和无权场馆不可访问。

员工入口/agent和/drafts，管理员/admin/approvals。H1确认、H2提交、H3审核独立；通过不占档、不改原排期或通知客户。成功须检查SSE终态、引用及实际记录。

## 日常巡检
每日检查服务、磁盘、模型、失败请求和备份；业务负责人核对待审核及异常队列，不自动清空积压。每周建议抽查5条审批与草稿、版本和意见，需人工执行。

每月复核账号、部门和场馆审核权，统计模型费用及超时。日志按request_id定位，导出脱敏；数据库、checkpoint、签名和真实资料不入公共仓库。留存期限及删除责任由上线单批准。

## 账号维护
停服后执行python scripts/manage_users.py reset-password --username demo.employee可交互重置并撤销其会话。停用执行python scripts/manage_users.py set-active --username demo.employee --disabled；启用用--enabled。维护完成重新启动并核验权限，不修改数据库绕过应用授权。

## 停机备份
通知业务暂停，用运行终端Ctrl+C正常停服并确认端口关闭，不终止不明进程。连接关闭后备份完整CHAT_DATA_DIR，含业务库、checkpoint、签名及SQLite伴随文件；同时记录并备份RAG_WORK_DIR的制度、索引与模型版本。禁止运行中仅拷一个数据库。

停服后用Copy-Item -LiteralPath复制两个完整目录到带日期的独立备份，禁止覆盖旧备份；用Get-FileHash -Algorithm SHA256留摘要。备份限制访问并加密，摘要不含密钥正文。锁状态由OS管理，不能从锁文件推定。

## 恢复与回退
1. 停止服务，保留故障目录和版本信息；禁止直接覆盖唯一现有副本。
2. 在新的隔离路径恢复同一次停机快照中的业务库、checkpoint与签名材料；恢复匹配的制度和索引版本。
3. 用匹配源码和依赖启动，将CHAT_DATA_DIR及RAG_WORK_DIR指向恢复路径；不得同时启动两个进程读写同一业务目录。
4. 先用Python sqlite3执行PRAGMA integrity_check核验业务及断点库，再核对账号、5份草稿、审批事件与等待确认状态；校验过程只读，不消费确认。
5. 在隔离环境用专用演示run确认刷新不会重建草稿。签认恢复结果后再切回服务；旧页面要求重新登录和刷新。

建议试点RPO为24小时、RTO为4小时，需实际计时演练并写明数据截点、起止时间、检查结果和批准人。版本升级前完成停机备份并在副本验证迁移；数据库迁移后不能盲目回退旧代码，优先恢复匹配代码与数据快照，业务变化另行人工对账。

## 故障处置
| 现象 | 检查与处理 | 禁止操作 |
| --- | --- | --- |
| 第二实例拒绝启动 | 查同目录实例和实际运行终端 | 删除锁文件后强行并发 |
| 无法登录或403 | 查账号状态、部门和当前场馆授权 | 开启旧演示身份旁路 |
| 409资料变化 | 刷新详情，重新核对版本与摘要 | 自动重放旧审核决定 |
| 模型超时或断线 | 查终态及已用轮次，再读草稿事实 | 因总结失败重复建单 |
| 制度或模型缓存不可用 | 查目录、下载条件和制度版本 | 编造无依据回答 |
| 数据库或磁盘失败 | 停止写入，保全目录并恢复演练 | 手改状态标为成功 |

## 上线准入和交接签认
受控试点前完成需求范围、规则、岗位、样本、资源及权限签认；通过第06册适用验收与25项上线清单。未建设的P1明确排除并关闭入口，不得填“已通过”。生产接入另完成SSO、制度ACL、HTTPS入口、安全、并发、灾备和正式业务事务设计。

交接单记录制品版本和摘要、配置与数据目录、备份位置、最近恢复演练、已知限制、未关闭缺陷、业务和维护责任人及签收日期。全部留空项为待填写，不能由本手册自动视作已签收。
