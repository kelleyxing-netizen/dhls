# 设计与成果维护

## 业务范围

围绕场馆档期申请的四段主链：意向询期、占档确认、合同审核、进撤场计划。现阶段研究只读导出、版本及来源关联、确定性冲突提示和人工确认，不执行生产占档或签约。

原始材料为合成访谈。行业事实、访谈假设、分析推断与实施建议应始终分开；费用和工时不能从虚构基线外推。

## 成果组织

- `data/source/`：用户提供的合成访谈原件，保留来源标识。
- `docs/reports/`：正式 DOCX 和内容对应的 Markdown。
- `docs/assets/`：定稿流程图；不保存裁剪预览和检查拼图。
- `docs/process/`：节点、风险与角色说明，以及可编辑 Mermaid。
- `.research/`：本机工作文件和视觉校验结果，Git 忽略。

## 代码组织

`src/dhls/main.py` 分发命令；`core/generate.py` 调用保留的生成脚本；`core/validate.py` 检查成果结构和发布链接；`utils/` 统一解析路径与字体。历史研究内容在 `scripts/build_report.py` 中，不会动态查询互联网。

配置采用 JSON，避免为少量静态路径引入额外解析依赖。字体只使用本机已安装文件，不打包微软或其他字体。

## 审核与发布

正文和表格统一使用微软雅黑，报告维持13页的已校验版式。修改 Word 后必须渲染再检查；CI 对字体、表格和链接的检查不能证明版面没有问题。

流程图采用15节点：11个操作、4个人工判断；风险标签分为费时、潜在成本、人工、隐私授权。调整图像时必须同步检查节点说明和 Mermaid，生成脚本只重绘图像。

AI转型目标图另用17节点、4个判断点表示拟建流程，系统自动处理、AI候选生成与人工审核办理分别着色。PNG、说明与Mermaid从同一目标模型生成，所有返回路径和审批闸门均保留；该模型不执行业务动作，试点继续只读脱敏、不自动锁档或签约。

发布使用普通提交和快进推送。后续每轮同步遵循根目录 AGENTS.md，不运行后台监控，不把凭据保存在仓库。
